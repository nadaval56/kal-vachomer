# סגולת הקל וחומר

אתר סטטי סביב סדר הלימוד והתפילה לרפואה של מרן הבן איש חי -
**לשון חכמים, חלק ב, סימן טז**.

| | |
|---|---|
| **`/`** | הלימוד והתפילה. חמשת קטעי הקל וחומר והתפילה שאחריהם, בנוסח לשון חכמים. עמוד אחד, גלילה אחת. |
| **`/study/`** - *העמקה* | ארבעה חלקים נפתחים: ההנחיה · הרעיון · העדות · ההשמטה. |

## איך זה בנוי

```
data/*.json        ← כל התוכן. מקור אמת יחיד.
scripts/build.mjs  ← מרנדר ממנו את index.html ו-study/index.html
index.html         ← נוצר. לא לערוך ידנית.
study/index.html   ← נוצר. לא לערוך ידנית.
sitemap.xml        ← נוצר. לא לערוך ידנית.
robots.txt         ← נוצר. לא לערוך ידנית.
assets/            ← style.css, app.js, og.png, גופנים
```

**לשנות תוכן:** לערוך את `data/*.json`, ואז `node scripts/build.mjs`.

ה-HTML הבנוי מקומט לריפו כדי ש-GitHub Pages יגיש קבצים סטטיים בלי שום `fetch`
בזמן ריצה. ה-Action ב-`.github/workflows/pages.yml` בונה מחדש ו**נכשל אם ה-HTML
שבריפו אינו תואם ל-JSON** - כך אי אפשר לשכוח לבנות.

### למה build ולא fetch מהדפדפן

המפרט המקורי תיאר `app.js` שקורא JSON. העדפתי רינדור בזמן build: הטקסט המנוקד
מגיע בגוף ה-HTML, נקרא גם בלי JavaScript, נדפס נכון, ואין הבזק של עמוד ריק ליד
מיטה בשלוש לפנות בוקר. `app.js` נשאר רק להתנהגות - גודל גופן, מצב לילה, שיבוץ
השם, ופתיחת כל החלקים לפני הדפסה.

### חתימת תוכן על הנכסים

`style.css`, `app.js` ו-`og.png` מקבלים `?v=<hash>` שמשתנה עם התוכן. בלי זה
דפדפן שכבר ביקר באתר מקבל CSS ישן מול HTML חדש, וזה נראה כאילו האתר נשבר.

### נראות במנועי חיפוש

הרינדור בזמן build הוא כבר חצי מהעבודה: כל הטקסט יושב ב-HTML, וזוחל שאינו
מריץ JavaScript קורא את האתר במלואו. לצד זה נוצרים מ-`meta.siteUrl`:

- `<link rel="canonical">` ו-`og:url` בכל עמוד - כתובת אחת מוצהרת, כדי
  ששתי כתובות לאותו תוכן לא ייחשבו לשני דפים.
- `sitemap.xml` - שני העמודים. בלי `lastmod`: תאריך שמשתנה בכל build הוא
  רעש בהיסטוריה.
- `robots.txt` עם הפניה למפה. **זוחלים קוראים רק את `robots.txt` שבשורש
  הדומיין ולא את זה שבתיקיית הפרויקט** - ומאז ש-`CNAME` מפנה את האתר
  ל-`kal-vachomer.co.il`, שורש הריפו הוא שורש הדומיין והקובץ אכן נקרא.
- `application/ld+json` - `WebSite` ו-`WebPage`, ובעמוד הראשי גם `about`
  שמצביע על ״לשון חכמים״.

מה ש**אינו** נעשה מהקוד: אינדוקס בפועל. גוגל מגיע לאתר חדש דרך קישורים
נכנסים או דרך הגשה ידנית ב-Search Console. בלי אחד מהשניים הדפים יכולים
לשבת שם זמן רב בלי שאיש ימצא אותם.

חמשת הלימודים לקל, לחומר, לצד השווה ולמסקנה. הוא הוסר מהתצוגה לבקשת הבעלים,
והנתונים נשמרו בכוונה. כדי להחזירו צריך גם לחבר אותו חזרה ב-`renderStudy`.

### על הנוסח

- הטקסט הוא נוסח ״לשון חכמים״ כפי שנמסר. הוסרו טעמי המקרא, הושלם ניקוד
  במקומות שנמסרו בלעדיו, ושמות הקודש נכתבו בכינוי.
- הציטוטים מבני יששכר ומבן יהוידע נוקדו לצורך הקריאה; הקיצורים שבמקור נשמרו.
- **מקפים קצרים בלבד** בכל האתר. גם הטקסט שנמשך מספריא מנורמל כך.

## ספריא

`scripts/fetch-sefaria.mjs` בונה את שכבת העיון שבסוף כל קטע בעמוד הראשי:
ביאור שטיינזלץ, הפסוקים, רש״י, ברטנורא, תוספות יום טוב, רמב״ם על המשנה,
תוספות, מהרש״א. נשמר ל-`data/commentary.json`; **הדפדפן לעולם אינו פונה
לספריא.** אם הקובץ ריק, השכבה פשוט אינה מוצגת והאתר עובד.

איך זה נשאר רלוונטי ולא הופך לערימה:

- **עוגני איתור.** לכל לימוד מוגדרות מחרוזות קצרות. הסקריפט מושך את הדף,
  מאתר את הקטע שבו נמצא הלימוד שלנו, ומביא פירושים על אותו קטע בלבד.
- **סינון.** מתקבל רק פירוש על החיבור שלפנינו, או על פסוק שהוא מצטט. פירוש
  שמפנה למסכת אחרת הוא הפניה ולא פירוש, ונדחה.
- **`curate`.** מה שספריא מחזירה אינו תמיד שייך. `drop` מוריד מפרש שלם,
  `keep` בורר פריטים לפי מדד. הליקוט יושב בסקריפט ולא בקובץ הנתונים, אחרת
  הרענון הבא היה מוחק אותו.
- **`steinSpan`.** בפסחים ובברכות הלימוד משתרע על כמה קטעים בספריא, ואיסוף
  של קטע אחד נותן ביאור חתוך. השדה אוסף את כל הטווח לפי עוגני פתיחה וסיום.
- **ניקוי.** טעמי מקרא, ישויות HTML, הערות נוסח, אות סימון הקטע של ספריא,
  ומקפים ארוכים.
- **מראי מקום בעברית.** ספריא לא מחזירה אותם, אז הסקריפט ממיר בעצמו:
  `Chidushei Agadot on Berakhot 5a:18` ← `מהרש״א, ברכות ה׳ ע״א`. מה שלא
  מזוהה נשאר באנגלית ולא מנוחש.

```bash
node scripts/fetch-sefaria.mjs --dry --verbose    # בדיקה בלי כתיבה
node scripts/fetch-sefaria.mjs --probe            # מדפיס את קטעי המקור
```

**מצב הסקירה שימושי.** כשצריך לבחור עוגנים או להבין למה משהו לא נמצא, `--probe`
מדפיס את מפת הקטעים של ספריא במקום לנחש. אפשר להריץ אותו גם מ-Actions: הפעלה
ידנית של `sefaria.yml` עם `probe` מסומן מדפיסה ולא כותבת דבר. אפשר להוסיף
מקורות לסקירה בלבד ב-`PROBE_EXTRA`.

הרענון רץ ב-`.github/workflows/sefaria.yml` (חודשי, או ידנית). אם הבקשות
נכשלות הסקריפט יוצא בהצלחה ואינו דורס את הקובץ הקיים. **הטקסט הראשי אינו
מוחלף בנוסח ספריא לעולם.**

## תמונת השיתוף

`assets/og.png` (1200×630) היא מה שנראה בתצוגה המקדימה בוואטסאפ. היא נוצרת
מ-`scripts/og-card.html`, שמושך את אותם גופנים וצבעים של האתר.

```bash
npm i -D playwright && node scripts/make-og.mjs
```

ה-PNG מקומט, כך שהבנייה הרגילה אינה תלויה ב-playwright.

**אין פסוק באף מטא-תג** - לא בכותרת, לא בתיאור, לא בתמונה ולא בטקסט החלופי
שלה. מטא-דאטה נחשף למי שלא פתח את הקישור. הפסוקים נמצאים בגוף הדפים בלבד.

## עיצוב

- גופן יחיד: **Assistant** (SIL OFL), מוגש מהריפו. יש בו את כל סימני הניקוד
  ומיקום GPOS נכון.
- **טעמי המקרא הוסרו מן הטקסט.** אין גופן עברי חופשי שכולל גם טעמים וגם מראה
  מודרני, וההכרעה הייתה לוותר על הטעמים ולא על הגופן.
- הדגשות בצבע בלבד. כל רקע או קו תחתון היה מתנגש בניקוד.
- מצב לילה, ושלוש מדרגות גופן שנשמרות ב-`localStorage`.
- שם החולה ב-`sessionStorage` בלבד. אין אנליטיקס, אין קוקיז, אין שירות חיצוני.

### הדפסה

עמוד הלימוד נכנס ל-**A4 אחד**. שני דברים שקל לשבור בלי לשים לב:

- **`html[data-size]` גובר על `:root` בספציפיות.** בלי להשוות את הבורר בבלוק
  ההדפסה, `--fs` נשאר בגודל המסך וכל מה שמבוסס `em` נדפס גדול פי שניים.
- **פרק סגור אינו מודפס.** הדפדפן משמיט את תוכנו של `<details>` סגור, ולכן
  `app.js` פותח הכול ב-`beforeprint` ומחזיר אחרי כן.

אחרי שינוי בגיליון הסגנון כדאי למדוד את דף ההדפסה בפועל, לא רק להסתכל עליו.
